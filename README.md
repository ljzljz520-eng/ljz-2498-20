# Catalpa 文稿平台 · 发布校对关口（Proofreading Gate）

在"保存 → 发布"之间增加一道**可解释、原子、可追溯**的校对关口。
前端 Vue 3 + Vite，后端 Node.js（内置 `http`），关系库 SQLite（`better-sqlite3`，
事务级强一致），无额外 Web 框架依赖。

## 三种状态严格区分

| 状态 | 含义 |
|---|---|
| **内容已保存** | 正文/属性落库（正文修订号 `body_rev`），**不**代表校对通过 |
| **校对通过** | 某次扫描在当前规则版下无未豁免阻断问题，且**依赖清单仍有效** |
| **已经发布** | 发布事务成功，存在一个**不可变的确定快照**与文档发布指针 |

校对通过不会自动发布；旧的校对通过可能因**正文之外**的变化而失效。

## 校对的四类问题（界面逐项可定位）

1. **标题层级** `heading.skip`：H2 后直接 H4 等跳级（定位行号 + 文本）
2. **空链接** `link.empty`：`[文字]()`、空 href（定位行号 + 链接文字）
3. **批注** `comment.open`：仍打开的批注（定位批注 ID + 行号）
4. **资源说明** `asset.description`：图片缺 alt/版权说明（定位资源 ID + 行号）

每个问题生成稳定指纹 `sha256(规则码 + 行内定位 + 规范化文本)`。

## 依赖清单：为什么不能只比较更新时间

扫描时生成依赖清单，记录正文修订、逐标题/链接内容哈希、每个资源的
`status_rev/withdrawn_rev`、每条批注的 `status_rev/open`、作者权限 `perm_rev`、
规则版以及被使用的豁免。**发布事务内逐项重新读取并比对版本**：

- 正文一个字没改，但**图片被撤回** → 资源撤回版本失配 → 拒绝；
- **批注被重新打开**（扫描时是已解决）→ 批注状态版本失配 → 拒绝；
- **作者权限改变**（作者被移除）→ 权限版本失配 → 拒绝；
- 标题被改、规则版升级、豁免被撤销/超出版本范围 → 对应依赖失配 → 拒绝。

拒绝响应逐条给出"哪一项依赖变了"，可直接解释给作者。

## 豁免：限定具体问题与版本，不被同类错误继承

豁免 = `(文稿, 规则码, 指纹, 有效版本区间, 理由)`，发布时还会用当前状态
**重跑一遍校验并重新匹配豁免**：

- 只豁免扫描到的**那一个**问题；同一行新增另一个空链接，指纹不同 → 不继承旧理由；
- 豁免只在申请时的正文修订区间内有效，正文再变即失效；
- 规则版升级后旧豁免不再自动适用。

## 方案比较：为什么选"预检 + 发布事务内权威复核"

- **方案 A（全部检查放进发布事务）**：资源外链检查可能很慢/迟到，长事务持锁、
  并发互相阻塞；发布前看不到逐项问题，失败不可解释。
- **方案 B（本项目）**：
  1. **扫描**同步跑本地校验、登记外部资源校验任务（可能"迟到"），产出逐项问题与依赖清单；
  2. **发布**在单个 `BEGIN IMMEDIATE` 事务内：锁文档行 → 逐项复核依赖版本 →
     复核资源任务终态 → 重跑校验并匹配豁免 → 写不可变快照、移动发布指针，一次性提交。

  - **读不到半套结果**：任何一步失败整体回滚，外部不可能看到"指针动了、快照没写"；
    `published_versions.scan_id` 唯一约束兜底，一次通过最多产生一个正式版。
  - **可解释**：发布前有完整逐项清单；被拒时精确到失配依赖。
  - 并发发布由即时锁 + `SQLITE_BUSY` 有界重试串行化；幂等键支持任务安全重试。

详见 [`docs/design.md`](docs/design.md)。

## 运行

```bash
npm install          # 已有 node_modules 可跳过
npm run build        # 构建前端到 dist/
npm run server       # 启动后端（默认 8080，同时托管 dist/ 与 /api）
# 打开 http://localhost:8080
```

开发模式（热更新）：

```bash
npm run server       # 终端1：后端 8080
npm run dev          # 终端2：Vite 3000，已配置 /api 代理到 8080
```

环境变量：`PORT`（后端端口，默认 8080）、`GATE_DB`（SQLite 文件路径）、
`AUTO_ASSET=1`（后台自动完成"迟到"的资源校验；默认手动，便于演示）。

## 界面操作路径

1. 编辑正文 → **保存内容**（状态条只亮"内容已保存"）；
2. **扫描校对** → 问题面板按四类分组，点"定位"跳转正文行；
3. 资源校验"迟到"时，可手动"送达迟到的校验结果"模拟外部回调；
4. 对个别问题可"申请豁免"（需重新扫描生效）；
5. 校对通过后 **发布正式版**；底部按钮可一键测试并发 ×3 与任务重试；
6. "世界事件与故障注入"面板：撤回图片、重开批注、改作者权限、升级规则版、
   开启发布瞬间数据库中断，随后观察旧通过如何被原子拦截。

## 测试

```bash
npm run test:gate    # node --test，端到端真实 HTTP + 临时 SQLite 库
```

覆盖：

- 四类规则逐项定位与指纹；
- 并发点击发布（同键/不同键）只有一个确定快照；
- 扫描后修改标题；
- 正文未变：图片撤回 / 批注重新打开 / 作者权限改变；
- 资源校验迟到；
- 任务重试幂等；
- 豁免绑定具体问题与版本、同类新错误不继承、规则版升级失效；
- 数据库中断时零提交、恢复后安全重试。
